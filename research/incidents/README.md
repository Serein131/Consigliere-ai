# 从误判到回归测试

在仓库根目录执行 `python research/replay_incidents.py --output incident-report.json`。报告包含代码提交、案例集摘要、逐项预期和实际标签、误报、漏报和失败清单。请使用干净的提交做正式比较。每次 PR 的 DealGuard Regression 都运行这条命令并上传报告。

1. **收集。** 从用户自愿反馈或测试失败开始。记录界面的审计编号、版本、模式、私下复核的原文证据。编号供用户与自己的记录关联，服务端没有可按编号查询的谈判档案。公开仓库只收录虚构或人工重新编写的最小案例，不上传真实客户文本、录音、报价单或签名回执。
2. **标注。** 按 reviewed.json 的结构填入唯一 ID、虚构输入、结构化底线、过去输出及期望标签。歧义先标 UNKNOWN。请第二位评审者独立判断再核对，分歧记录在待审材料，未解决不设为发布门槛。当前四例为开发回放，未获独立专业评审。
3. **归因。** 先看原文是否有证据，再核对抽取的数值、状态、阈值和最终对外话术。原文有明确证据而规则漏读，修改解析规则。模型错读否定或角色，先用同一模型测试提示词。数值已正确但回复越线，修复输出约束。只有同一提示词在多类独立样本上持续失败，才比较模型。
4. **比较。** 一次只改一层。先保留修改前的报告，再用同一批案例复跑，对照案例 ID，分别看漏报、误报和 UNKNOWN。模型实验使用仓库内现有四组评测脚本，保留模型标识、提示词版本和每次输出，报告缺失及不稳定结果。
5. **回归。** 对每次修复加入至少一个容易误报的反例。已评审案例或基础集出现不匹配，回放命令返回非零。挑战集用于定位问题，已用于调试的案例归入开发集；判断泛化能力需要一批新封存案例。CI 失败是否阻止合并取决于仓库分支保护设置。
